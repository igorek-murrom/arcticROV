# Архитектура и расширение

## Почему локальный сервер

Верхний блок запускает Node.js-сервис и обслуживает браузеры. Интернет и облачный сервер не требуются. Сервис хранит авторитетное состояние оператора; браузеры не могут назначить себя владельцами или напрямую отправить тягу в адаптер. Сейчас весь пакетный выход потребляет симулятор.

```text
Браузеры: клавиатура / Gamepad API
        ↓ POST /api/command, 20 Гц
HTTP-сервер → контроллер права управления
        ↓ валидация действий, возрастающий seq, epoch, свежесть
Защита: arm + deadman + нет e-stop + свежая команда
        ↓ нейтральное состояние при любом запрете
Матрица смешивания → пакет v1
        ↓ цикл 20 Гц
Адаптер Simulator.apply(packet)
        ↓ Simulator.step(dt)
Телеметрия + состояние → SSE 10 Гц → все браузеры
```

Зависимостей npm нет, приложение работает без сборки и CDN. `npm dev` перезапускает сервер при изменении файлов; после изменения браузерных модулей обновите страницу. Перезапуск уничтожает сеансы и журнал в памяти.

## Право управления

Получение права — атомарная операция в одном процессе Node.js. У каждого сеанса случайный bearer token, у каждой новой аренды отдельный `epoch`. Команды привязаны к обоим. Клиентский `seq` строго возрастает внутри аренды; повторные и переставленные команды отвергаются.

Одновременно возможен один запрос передачи. Он живёт 15 с и не отбирает управление без согласия. У запроса отдельный `requestId`: запоздавшее подтверждение или отклонение не затрагивает новый запрос. Повторное нажатие не продлевает старый запрос. Запросивший может его отменить; исчезновение его потока отменяет запрос. Все изменения владельцем проверяют текущий `epoch`.

Передача, освобождение, разрыв потока оператора и истечение аренды выключают выходы. Разрыв потока не отнимает право немедленно: прежний оператор может восстановить соединение в пределах 2-секундной аренды. Отдельный heartbeat раз в 500 мс поддерживает аренду, пока страница видима, независимо от фокуса, включения выходов и аварийного стопа. Heartbeat не обновляет возраст команды движения и не включает выходы. Отсутствие команд более 350 мс по-прежнему выключает выходы. Восстановление связи или команд не включает выходы автоматически.

Каждое выключение выходов меняет `safetyEpoch`. Команды, включение и сброс стопа требуют текущего значения: запоздавший сброс не снимает новую остановку, а отложенное включение не пересекает границу стопа. Аварийный стоп не меняет владельца. При передаче уже установленный стоп остаётся установленным.

Состояния содержат `stationId`, возрастающий `stateSeq` и последний принятый номер команды владельца. Браузер отвергает запоздавшие состояния и ответы от прежнего сеанса, а после обновления страницы продолжает нумерацию команд. Ошибки управляющих запросов содержат актуальное состояние для немедленного обновления владельца в интерфейсе.

Таймер сервера вызывается раз в 50 мс, поэтому фактическое программное обнаружение может наступить на следующем тике; Node.js и ОС не обеспечивают жёсткое реальное время. Таймер нижней платы должен работать независимо от этого цикла.

Любой вошедший участник может остановить аппарат. Сбросить стоп может владелец управления после свежей нейтральной команды без кнопки разрешения. Сброс не включает выходы.

`blur`, скрытие страницы, смена раздела и отключение выбранного геймпада выключают выходы. Сетевые таймеры работают на сервере независимо от обработчиков браузера. Вне вкладки пилотирования браузер отправляет только нейтральные команды.

## Сеансы и сеть

На loopback ввод кода не нужен. При открытии сервера на других интерфейсах генерируется общий однозначный код `0`…`9`, если не задан `ACCESS_PIN`. Его ввод создаёт случайный токен; токен хранится в `sessionStorage`, отдельном для вкладки, не передаётся в URL и не попадает в экспорт журнала. На токен разрешён один поток событий: дублированная вкладка с копией sessionStorage получает отдельный вход. Имена назначаются атомарно, с нормализацией Unicode, пробелов и регистра; занятому имени добавляется свободный суффикс. Явный выход освобождает имя сразу. Маршрут камеры использует ограниченную по пути HttpOnly-cookie, так как `<img>` не умеет задавать Authorization.

Контур рассчитан на доверенную локальную сеть. Общий код не даёт индивидуальных ролей и не шифрует HTTP. Для развёртывания за пределами стенда потребуются HTTPS, персональная аутентификация, роли оператора/наблюдателя/администратора и решение, кому разрешён принудительный захват. В текущем варианте принудительного захвата нет: активный оператор подтверждает передачу, при его исчезновении срабатывает аренда.

SSE передаётся через `fetch` с Authorization. Сервер ограничивает размер запросов, количество сеансов/потоков, частоту попыток входа и разрывает зависшие потоки с накоплением очереди. Origin проверяется, CORS для посторонних сайтов не разрешён. Имена участников и отметки выводятся как текст.

## Добавить аналоговое действие

Например, вращающийся инструмент:

1. В `shared/actions.mjs` добавить запись:

```js
{ id: 'tool', label: 'Вращение инструмента', kind: 'axis',
  negative: 'KeyZ', positive: 'KeyX', padNegative: 8, padPositive: 9,
  group: 'Оборудование' }
```

2. Редактор привязок, обработчик аналоговых действий, нейтральные значения, проверка входа и поле `packet.actions.tool` появятся автоматически.
3. В симуляторе определить модель реакции на `a.tool`, а в будущем аппаратном адаптере — соответствующий выход. В интерфейсе при необходимости добавить его телеметрию.
4. Поскольку реестр изменился, старый профиль может больше не пройти валидацию: приложение восстановит стандартный. Для долгоживущих профилей нужно добавить миграции версий.

Новое действие типа `toggle` автоматически получает сохранённое состояние и обработку фронта кнопки в `shared/input.mjs`. Оно переключается один раз при нажатии, а не на каждом тике удержания. Выключение всего оборудования является текущим нейтральным поведением; для нагрузок, которым нужна другая политика отказа, её нужно явно согласовать и реализовать на обоих уровнях.

## Сменить схему движителей

Редактировать `vehicle.thrusters` в `server/vehicle.mjs`: коэффициенты `mix` для каждой оси. Суммы нормализуются с сохранением пропорций, затем умножаются на `maxPower` и переводятся в проценты. В текущем UI подготовлено шесть индикаторов, поэтому для другого количества измените создание индикаторов в `public/app.mjs` и подпись схемы. Это намеренно явная настройка оборудования, недоступная наблюдателям.

Для текущего примера максимальный предел сервера — 60%; чувствительность браузера дополнительно ограничивает пользовательский ввод. Значения не являются калиброванной физической тягой или ШИМ. Направление каждого движителя проверяется отдельно; знаки прежней восьмидвигательной схемы не перенесены.

## Реализовать аппаратный адаптер

Адаптер имеет методы `apply(packet)`, `step(dt)`, `telemetry()`. Сохранить серверный арбитраж и валидатор. Разделить цикл симуляции и асинхронный транспорт: подтверждения и телеметрия должны определять фактическое состояние связи. Не показывать «на связи» только на основании успешной отправки UDP/Serial.

Пока класс Simulator создаётся явно в `createStation()`. Реальный адаптер подключать отдельным явным режимом после реализации требований протокола. Не подменять отсутствие датчиков синтетическими значениями в физическом режиме.
