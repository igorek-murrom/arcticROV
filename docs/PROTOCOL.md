# Команды и будущий нижний блок

## Реализованный пакет

Сервер формирует объект 20 раз в секунду. Сейчас его принимает только программный Simulator; **передачи в Serial/UDP/MAVLink нет**.

```json
{
  "protocol": "rov-control",
  "version": 1,
  "seq": 124,
  "serverTime": 12345.67,
  "ttlMs": 350,
  "armed": true,
  "estop": false,
  "deadman": true,
  "thrusters": [18, 18, 18, 18, 0, 0],
  "actions": {
    "surge": 0.3,
    "sway": 0,
    "heave": 0,
    "yaw": 0,
    "cameraTilt": 0,
    "grip": 0,
    "wrist": 0,
    "light": 1
  }
}
```

`thrusters` — целые проценты −60…60 для текущей конфигурации. Это команда ESC-адаптеру, не длительность PWM. `actions` — логические действия −1…1. `cameraTilt`, `grip`, `wrist` являются **скоростными командами**, не абсолютными положениями. Положительный `heave` направлен вверх, `grip` — открывание, `wrist` — положительное вращение, `light` равен 0 или 1. Скорости и предельные положения в Simulator — демонстрационные.

Если выходы запрещены, кнопка разрешения отпущена или активен стоп, массив движителей и все действия нулевые. Камера и манипулятор в симуляторе сохраняют последнее достигнутое положение, свет выключается. Независимый ограничитель в адаптере проверяет `armed`, `deadman`, `estop` и возраст получения пакета.

`seq` возрастает в рамках процесса верхнего ПО; это не номер входной команды браузера. `serverTime` — монотонное время верхнего процесса для диагностики. Его **нельзя сравнивать с millis() платы**. `ttlMs` означает максимальный локальный интервал после получения валидной команды.

## Браузер → верхний блок

`POST /api/command` с bearer token:

```json
{
  "epoch": "идентификатор-текущей-аренды",
  "seq": 12,
  "issuedAt": 12345.67,
  "deadman": true,
  "values": { "surge": 0, "sway": 0, "heave": 0, "yaw": 0,
    "cameraTilt": 0, "grip": 0, "wrist": 0, "light": 0 }
}
```

`issuedAt` копируется из последнего состояния **сервера**, чтобы не зависеть от синхронизации часов браузера. Команда с таким временем старше 400 мс отвергается. Токен аутентифицирует участника, epoch защищает от очереди команд прежнего владельца, seq защищает от повторов и перестановки. Сервер не принимает произвольный массив тяг от браузера.

## Что согласовать после выбора платы

1. **Транспорт:** Serial через кабель/конвертер, UDP поверх Ethernet или иной канал. Сервер должен иметь физический доступ к нему; вкладка оператора этим не занимается.
2. **Формат на проводе:** текущий JSON — явный договор действий, но не окончательная двоичная спецификация. Для малой платы выбрать фиксированную схему, предел размера, проверку длины/версии/CRC и правила кадрирования. Не отправлять сырые C++-структуры с зависимым padding и endianness.
3. **Рукопожатие:** версия, идентификатор аппарата, число движителей, список возможностей, пределы, идентификатор загрузки/сессии, состояние firmware-ready. Перезапуск любого конца требует нового рукопожатия и отдельного arm.
4. **Независимая защита:** плата загружается с нейтральными ESC; при отсутствии валидных свежих команд локальный таймер обнуляет выходы. Пакеты с неверной контрольной суммой, неизвестной версией или повторным seq не обновляют этот таймер. Повторное включение после отказа явно согласуется.
5. **Подтверждение:** телеметрия содержит последний применённый seq, реальное armed/estop, причины запрета, признаки протечки, состояние питания и датчиков. Изменение положения манипулятора в UI требует обратной связи или честной отметки «расчётное».
6. **Ограничения:** нейтраль PWM, реверс и калибровка ESC, нарастание тяги, аппаратные пределы сервоприводов, политика для света/нагревателя/насоса при отказах.
7. **Испытания:** без винтов, стенд под нагрузкой, выдёргивание кабеля, зависание/перезапуск верхнего блока, потеря телеметрии, повреждённые пакеты и сбои питания. Программный E-stop в браузере не заменяет физическую защиту силовой части.

Не включать реальный транспорт простым перенаправлением текущего JSON в старую RovFW2: форматы не совпадают, а независимой остановки по свежести в рассмотренном основном цикле прежней прошивки нет.
