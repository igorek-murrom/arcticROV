# АРКТИКА — станция управления ТНПА

Рабочая первая версия верхнего ПО. Запускается на компьютере верхнего блока, участники открывают пульт в браузере. Сейчас подключён только **симулятор**: настоящая плата, двигатели и датчики не задействованы.

## Запуск

Требуется Node.js 22 или новее. Зависимостей для установки нет.

```bash
cd /home/igor/Documents/rovNEW
npm start
```

Открыть <http://127.0.0.1:8080>, ввести имя. Вторая вкладка или другое окно — отдельный участник. Во вкладке, созданной дублированием уже открытой, браузер может скопировать сеанс: для отдельного участника нажмите аватар и войдите заново.

Для подключения с других компьютеров в доверенной локальной сети:

```bash
HOST=0.0.0.0 npm start
```

Сервер напечатает код доступа. Участники открывают `http://IP-ВЕРХНЕГО-БЛОКА:8080` и вводят этот код. После перезапуска код меняется. Для постоянного кода задайте `ACCESS_PIN` в окружении. Доступ всех участников равнозначен: каждый может запросить управление или нажать аварийный стоп. Это базовая защита локального стенда, без персональных аккаунтов и ролей.

**Геймпады:** Gamepad API требует защищённого контекста. На `localhost` современные браузеры обычно разрешают его без HTTPS; при открытии по IP с другого компьютера потребуется HTTPS на верхнем блоке, например через настроенный локальный reverse proxy. Пульт показывает причину недоступности. Клавиатура работает и по HTTP. Геймпад нужно подключить и нажать на нём кнопку, чтобы браузер обнаружил устройство.

## Первый тест без электроники

1. Войдите и нажмите «Получить управление».
2. Отпустите клавиши и стики. Нажмите «Включить выходы».
3. Удерживайте **Space** и нажимайте **W/A/S/D**. Виртуальная сцена и значения тяги меняются. Без Space выходы обнуляются.
4. **Q/E** — разворот, **R/F** — вверх/вниз, **↑/↓** — камера, **J/K** — закрыть/открыть захват, **U/I** — вращение манипулятора, **L** — свет.
5. **Esc** — аварийная остановка с фиксацией. Сбросить её может текущий оператор, отпустив управление; затем выходы нужно включить заново.
6. Во втором окне войдите с другим именем: оно видит ту же сцену, телеметрию и оператора. «Забрать управление» отправляет запрос. Текущий оператор подтверждает или отклоняет его. При передаче выходы выключаются.
7. Закройте окно оператора: право управления освобождается при закрытии потока событий или по истечении аренды через 2 с.

Расчётная исходная схема: 4 горизонтальных и 2 вертикальных движителя. Геометрия, направления и знаки являются **примером**, а не настройкой изготовленного аппарата. Глубина симулятора изначально 0 м: для погружения используйте Space + F.

## Настройки и данные

- Раздел **Управление**: клавиши, индексы осей и кнопок геймпада, инверсия осей, мёртвая зона, плавность, чувствительность, кнопка разрешения. Backspace в поле привязки очищает её; Esc отменяет привязку и одновременно останавливает выходы.
- Профиль сохраняется в браузере. Его можно экспортировать и импортировать в JSON. Наименование кнопок соответствует индексам Gamepad API, начиная с нуля; кнопка B5 — разрешение по умолчанию. Стандартные стики: A0/A1 — горизонтальное движение, A2 — разворот, A3 — камера, B6/B7 — вертикальное движение.
- Раздел **Аппарат и пакеты** показывает фактически формируемый сервером пакет.
- **Отметка** добавляет событие в журнал сервера; это доступно оператору.
- **Экспорт** скачивает JSON с телеметрией раз в секунду, командными пакетами и событиями текущего подключения. В памяти браузера хранится скользящее окно до 7200 отсчётов (около 2 ч), сервер хранит последние 100 событий. Видео не записывается, после закрытия браузера несохранённые отсчёты теряются.

## Камера

По умолчанию показывается подписанная синтетическая сцена. Для настоящего потока MJPEG или JPEG:

```bash
CAMERA_URL=http://192.168.1.20:8081/video npm start
```

URL задаёт владелец верхнего блока при запуске. Сервер передаёт поток в браузеры через свой защищённый сеансом маршрут. Телеметрия и управление при этом всё ещё относятся к симулятору, что отмечено в интерфейсе. RTSP и H.264 напрямую в этой версии не поддерживаются: нужен преобразователь в MJPEG или будущий WebRTC-адаптер. Фактический поток с вашей камеры ещё не проверен. Подключение к USB-камере средствами захвата видео также не реализовано.

## Как расширять

Схема и границы модулей: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Договор обмена с будущей платой: [docs/PROTOCOL.md](docs/PROTOCOL.md). Разбор прежних исходников: [docs/LEGACY_REVIEW.md](docs/LEGACY_REVIEW.md).

Ключевые места:

| Файл | Назначение |
| --- | --- |
| `shared/actions.mjs` | Действия, типы, исходные привязки, проверка профиля |
| `shared/input.mjs` | Универсальная обработка осей и переключателей клавиатуры/геймпада |
| `public/app.mjs` | Ввод, интерфейс, профили и связь с сервером |
| `server/controller.mjs` | Единственный оператор, аренда, проверка пакетов, остановки |
| `server/vehicle.mjs` | Матрица смешивания и предел тяги |
| `server/simulator.mjs` | Адаптер симулятора и модель датчиков |
| `server/index.mjs` | Локальный HTTP-сервер, сеансы, поток событий, цикл 20 Гц |

Новая команда добавляется в реестр действий; редактор, ввод, нейтральные значения, серверная проверка и пакет подхватывают её автоматически. Для неё нужно назначить поведение в адаптере. Поддерживаются оси и переключатели с обработкой фронта кнопки. Подробный пример есть в архитектуре.

## Проверка

```bash
npm test
```

Тесты проверяют конкуренцию операторов, передачу управления, устаревшие права и пакеты, ограничения тяги, аварийный стоп, тайм-ауты, валидацию профиля, нижний таймер симулятора и HTTP-сеансы. Для HTTP-тестов нужны свободные временные порты localhost.

## До настоящего погружения

Это основа для разработки и испытаний, **не проверенная система управления реальным аппаратом**. Сейчас нет аппаратного транспорта, рукопожатия с платой, подтверждений команд, прошивки, испытаний движителей или датчиков. Прежний протокол RovFW2 автоматически не используется. Также пока нет автопилота, удержания курса/глубины, записи видео, долговременного хранилища и отдельного права администратора.

После выбора платы нужно реализовать транспорт и согласовать нижнюю прошивку. Особенно важен независимый таймер остановки на самой плате: серверный тайм-аут не спасает при зависании верхнего компьютера. Для стенда ограничьте тягу и сначала проверьте направления без винтов. Дальнейшие решения перечислены в протоколе.
